## Reproduced and fixed

### DCK counts silently accepted malformed input

`DeckList.parse_dck()` used `to_int()` without validating the entire token.
A fixture with counts `2oops`, `1.5` and `3x` produced zero errors and six
unwanted card copies across the maindeck and sideboard. Both strict and
lenient modes did this; leniency is meant to allow unknown card names, not
malformed syntax.

The regression printed `[0] expected to equal [3]` for the error tally,
and the sideboard was `["Shatter", "Shatter", "Shatter", "Disenchant"]`
instead of `["Disenchant"]`. Counts now pass `is_valid_int()` before
conversion. Valid lines still load and every malformed count is reported.

### Ordinary DEC comments changed the deck title

Both `DeckList.parse()` and the fast provenance reader `DeckStore.title_in()`
treated any comment starting with `name` as a title declaration. Thus
`// Nameless idea: Also Changed` overwrote `// NAME : Keep This Title`.
Both regressions printed
`["Also Changed"] expected to equal ["Keep This Title"]`.

Both readers now require the field before the colon to be exactly `NAME`,
case-insensitively and with surrounding whitespace allowed. Ordinary
comments remain comments; valid existing NAME headers retain their behavior.

### Generated deck filenames were not Windows-portable

`DeckStore.path_for("CON")` returned `user://decks/con.deck`. The same
normalization exposed other DOS device stems. Windows reserves these names
even with extensions, according to Microsoft's
[file-naming documentation](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file).

`file_stem()` now prefixes these cases with `deck_` on every host, so a deck
created on Linux or macOS can travel to Windows. For example, `CON` saves
under `deck_con.deck`, while its title remains `CON` inside the file. All
22 ASCII device names, punctuation/case variants and nearby non-reserved
names are covered. Existing ordinary filename mappings are unchanged.
This is a filename-contract regression, not a claimed Windows runtime test.
